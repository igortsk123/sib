# review-sweep — LLM-прогон очереди «проверить» (запрос владельца 2026-07-26)

**Триггер автоматический**: таймер `sib-review-sweep.timer` (ежедневно 04:30) прогоняет
`/opt/sib-intake/review_sweep.py --apply` по СВЕЖИМ пометкам (где LLM ещё не смотрел —
`review_note` без «LLM»). Ручной запуск — по мере надобности; `--all` пересматривает и уже
смотренные. Каждая запись сверяется с ТЕКСТОМ ОРИГИНАЛА (вложение → raw .eml → тело).
Значения полей процедура НЕ перезаписывает.

## Критерии решения (консервативные)
- **Снять пометку** (`needs_review=false`, `review_note += '✔ LLM-сверка ok <дата>'`):
  ВСЕ переданные поля подтверждены письмом (`verdictOk=true`, ни одного `match=false`),
  `confidence ≥ 0.7`, у записи есть оригинал.
- **Исключить из реестра** (владелец 26.07: «вебинары и прочее — автоматом исключай»):
  LLM вернул `notDms=true` (приглашение/маркетинг/новости — вообще не письмо ДМС) →
  `doc_type='other'` (реестр скрывает «прочее» по умолчанию), `needs_review=false`,
  `review_note += 'исключено: не письмо ДМС'`. Данные НЕ удаляются (D6) — карточка доступна.
- **Оставить + конкретизировать** (`review_note += 'LLM: <что именно расходится>'`):
  найдено расхождение — человеку сразу видно, ЧТО проверять.
- **Пропустить**: нет оригинала; причина «в письме не найдено» (данных нет — LLM не поможет);
  LLM не уверен (<0.7).

## Промпт (система) — актуальная версия (v3, 2026-07-26)
```
Ты проверяешь запись реестра ДМС против текста письма страховой. Запись создана автоматически
и помечена «проверить». Сверь КАЖДОЕ переданное поле с письмом. Верни ТОЛЬКО JSON:
{"match": {"<поле>": true|false|null},        // null = в письме этого нет
 "inLetter": {"<поле>": "как в письме или null"},
 "verdictOk": true|false,                      // все переданные поля подтверждены
 "confidence": 0..1,
 "note": "коротко по-русски, что не так (если что-то не так)"}
Правила: сравнивай по смыслу (регистр/пробелы/формат дат не важны).
«Страховой полис» и «номер гарантийного письма/исходящий» — РАЗНЫЕ номера, не путай.
Статусы: enroll=прикрепление к программе, detach=открепление, approved=гарантия оплаты услуг,
annul=аннулирование ранее выданного письма, referral=направление.
Если поле в письме отсутствует — match=null. Точность важнее полноты: сомневаешься — false и ниже confidence.
ОТДЕЛЬНО: если письмо ВООБЩЕ не относится к ДМС/страхованию пациента (приглашение на вебинар,
маркетинговая рассылка, новости, реклама, служебное уведомление без пациента) — добавь "notDms": true.
ЗАМЕТКУ (note) пиши ПО-РУССКИ для менеджера клиники: названия полей русскими словами
(«статус», «полис», «номер письма», «срок действия»), статусы — словами («гарантия оплаты»,
«направление», «прикрепление»), НИКАКИХ английских терминов и кодов.
```

## Пользовательское сообщение
`ПИСЬМО:\n<текст ≤9000 симв (вложение → raw .eml → тело)>\n\nЗАПИСЬ:\n<JSON с РУССКИМИ ключами:
«ФИО пациента», «Полис», «Номер письма», «Статус» (словами), «Дата письма», «Срок действия»,
«Услуги»>\n\nПричина пометки: <review_note или поля с низкой уверенностью>`

Решение принимает КОД, не LLM: снятие — только при verdictOk и confidence≥0.7; notDms≥0.7 →
исключение (тип «прочее»); иначе пометка остаётся с русской конкретикой. Поля LLM не меняет никогда.

## Исключения страховых (правила владельца, D36)
`insurance_company.rules.recognitionExceptions` — список правил простым текстом; sweep подставляет
их в промпт для записей этой СК («ИСКЛЮЧЕНИЯ… — соблюдай строго»), видны на вкладке
«Распознавание и программы». Пример: СОГАЗ-«направление» с фразой «Гарантируем оплату
медицинских услуг» = ВИД гарантийного письма, статус «гарантия оплаты» верен.

## Приёмы массовой очистки (обкатано 26.07, очередь 536 → ~230)
1. **Сверка полей с оригиналом** (этот sweep): снято 251 + исключено 13 не-ДМС.
2. **Темы писем** (совет владельца): `subjects_sweep.py` — Subject из raw .eml (в БД пуст),
   явный мусор по ключам (ЭДО/ЭЦП/вебинар/акт сверки) + LLM-батч ТОЛЬКО по темам (дёшево,
   1 вызов на всё) → исключение «не ДМС». −28 записей.
3. **Обрезанные полисы**: `policy_fix.py` — полный номер ищется в тексте как ПРОДОЛЖЕНИЕ
   обрезанного префикса (прямое доказательство) → дозаполнение; +63.
4. **Хвостовой дефис РЕСО**: бланк сам печатает «номер полиса: NNNNN-NNN/NN-» с обрывом —
   это НЕ обрезка, хвостовой дефис срезается массово (50 шт), полис соответствует письму.

## Запуск
```
cd /opt/sib-intake && python3 review_sweep.py            # dry: отчёт без записи
cd /opt/sib-intake && python3 review_sweep.py --apply    # применить решения (только свежие пометки)
cd /opt/sib-intake && python3 review_sweep.py --all --apply  # пересмотреть и уже смотренные
```
Регулярность: вручную по мере накопления очереди (видно на /registry фильтром «Проверка»);
процедура идемпотентна — повторный прогон трогает только оставшиеся пометки.
ПДн уходит только в RU-прокси проекта (как весь LLM-трафик распознавания, ADR D10).
