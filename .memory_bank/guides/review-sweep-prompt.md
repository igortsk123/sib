# review-sweep — LLM-прогон очереди «проверить» (запрос владельца 2026-07-26)

Когда пометок `needs_review` накопилось много, запускается **отдельная процедура**
`/opt/sib-intake/review_sweep.py` (`--apply` после dry): каждая помеченная запись сверяется
LLM-ом с ТЕКСТОМ ОРИГИНАЛА письма (вложение → raw .eml → тело). Значения полей процедура
НЕ перезаписывает — только снимает или конкретизирует пометку.

## Критерии решения (консервативные)
- **Снять пометку** (`needs_review=false`, `review_note += '✔ LLM-сверка ok <дата>'`):
  ВСЕ переданные поля подтверждены письмом (`verdictOk=true`, ни одного `match=false`),
  `confidence ≥ 0.7`, у записи есть оригинал.
- **Оставить + конкретизировать** (`review_note += 'LLM: <что именно расходится>'`):
  найдено расхождение — человеку сразу видно, ЧТО проверять.
- **Пропустить**: нет оригинала; причина «в письме не найдено» (данных нет — LLM не поможет);
  LLM не уверен (<0.7).

## Промпт (система)
```
Ты проверяешь запись реестра ДМС против текста письма страховой. Запись создана автоматически
и помечена «проверить». Сверь КАЖДОЕ переданное поле с письмом. Верни ТОЛЬКО JSON:
{"match": {"<поле>": true|false|null},        // null = в письме этого нет
 "inLetter": {"<поле>": "как в письме или null"},
 "verdictOk": true|false,                      // все переданные поля подтверждены
 "confidence": 0..1,
 "note": "коротко по-русски, что не так (если что-то не так)"}
Правила: сравнивай по смыслу (регистр/пробелы/формат дат не важны; 46988550 = «полис 46988550»).
«Страховой полис» и «номер гарантийного письма/исходящий» — РАЗНЫЕ номера, не путай.
Статусы: enroll=прикрепление к программе, detach=открепление, approved=гарантия оплаты услуг,
annul=аннулирование ранее выданного письма, referral=направление.
Если поле в письме отсутствует — match=null. Точность важнее полноты: сомневаешься — false и ниже confidence.
```

## Пользовательское сообщение
`ПИСЬМО:\n<текст ≤9000 симв>\n\nЗАПИСЬ:\n<JSON полей: patientFullName, policyNumber, letterNumber,
approvalStatus, letterDate, validUntil, services>\n\nПричина пометки: <review_note или поля с низкой уверенностью>`

## Запуск
```
cd /opt/sib-intake && python3 review_sweep.py            # dry: отчёт без записи
cd /opt/sib-intake && python3 review_sweep.py --apply    # применить решения
```
Регулярность: вручную по мере накопления очереди (видно на /registry фильтром «Проверка»);
процедура идемпотентна — повторный прогон трогает только оставшиеся пометки.
ПДн уходит только в RU-прокси проекта (как весь LLM-трафик распознавания, ADR D10).
