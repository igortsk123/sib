# ПРОМПТ ЭКСТРАКЦИИ ПРАВИЛ ПОКРЫТИЯ (v3, обкатан на 3 документах)

**Исполнитель — агент сессии, читающий текст сам. Внешние LLM (GPT и т.п.) ЗАПРЕЩЕНЫ** (решение
владельца 2026-07-25). Промпт отлажен циклом «прогон 1 док → верификатор → правка промпта»;
результаты обкатки — в конце файла.

---

## 0. ОБЩАЯ ЧАСТЬ (для всех типов)

**Вход:** ПОЛНЫЙ текст документа из `document_text` (постранично), НЕ обрезанные фрагменты.
Дампер `dump_relevant.py` — только для навигации; экстракция всегда по полному тексту (или по
явно очерченным разделам — см. тип E).

**Выход** — строки `coverage_rule`:
`(document_id, insurance_company_id, program_name, service_class, service_pattern, verdict, condition_text, limit_amount, clause)`

**verdict:**
| значение | когда |
|---|---|
| `covered` | услуга прямо в объёме программы, без условий |
| `excluded` | «не оплачивается / не оказывается / исключение / не является страховым случаем» |
| `needs_approval` | «по согласованию со страховщиком», «по направлению», «через контакт-центр», непрямое прикрепление |
| `conditional` | покрыто при явном условии/лимите → условие сжато и ДОСЛОВНО по смыслу в `condition_text` |

**clause ОБЯЗАТЕЛЕН.** Форматы: `п. 3.2.7` · `п. 4.1.6 – 4.1.8` (диапазон) ·
`Раздел 1 «дословная фраза-якорь»` (для маркированных списков без номеров).
Правило: **либо числовой пункт, реально присутствующий в тексте, либо фраза в «ёлочках»,
находимая дословно** (верификатор проверяет и то, и другое).

**ЭКОНОМИКА — ОБЯЗАТЕЛЬНЫЙ ОТДЕЛЬНЫЙ ПРОХОД** (владелец 26.07: «важная экономическая
составляющая»). После основной экстракции прогнать по тексту документа детект конкретных цифр:
`\d[\d ]{2,}\s*(руб|₽)` и `франшиз\w*…\d+\s*%` (тарифные таблицы нетто-ставок — НЕ лимиты,
пропускать). Каждая найденная сумма/процент обязана попасть в правило: `limit_amount`
(«5 000 руб. в год», «400 руб. за курс», «франшиза 10%») + условие в `condition_text`.
Механизмы без цифр («франшиза устанавливается договором») — правило-условие БЕЗ limit_amount.
Конкретные страховые суммы/франшизы обычно живут в ДОГОВОРЕ клиники — при заведении договора
(source='clinic') экономический проход обязателен вдвойне. Детект-SQL — `coverage-sql/economics-*.sql`.

**service_class** (закрытый словарь): `стоматология-приёмы | стоматология-терапия |
стоматология-хирургия | стоматология-ортопедия | стоматология-физио | стоматология-профилактика |
протезирование | имплантация | ортодонтия | пародонтология | амбулатория-приёмы |
амбулатория-манипуляции | диагностика | физиотерапия | лекарства | документы-справки | стационар |
общие-исключения | общие-условия`.

**service_pattern** — нормализованные ключевые слова из текста, нижний регистр, без склонений
(«удаление зуб», «имплантац»). **Паттерн одной услуги не должен быть подстрокой другой:**
«удаление зубного камня» ловится запросом «удаление зуб» → писать «зубной камень снятие отложений».
Контроль — SQL из §4 п. 6.

**program_name** — точное название программы; `NULL` = правило уровня страховой (общие исключения
правил). Варианты программы («… - РЕГИОНЫ», «(ЭКОНОМ)») — ОТДЕЛЬНЫЕ наборы правил, дублирование
допустимо и желательно (ретрив идёт по названию программы из полиса).

**Принципы качества:**
1. Только явный текст. Ничего не выводить логически, не обобщать «наверное», не додумывать лимиты.
2. «X, за исключением Y» → ДВА правила: X `covered` + Y `excluded`/`conditional`.
3. Составные пункты ДРОБИТЬ по услугам («удаление зубов; цистэктомия; резекция верхушки; вскрытие
   абсцессов» = 3-4 правила): ретрив ищет по услуге, крупный ком не найдётся.
4. **Порядок получения услуг — тоже правила** (частая потеря): прямое/непрямое прикрепление,
   «учреждение определяет страховщик», обращение в контакт-центр, регистрация карты/франшизы →
   `needs_approval`/`conditional`, класс `общие-условия`. Для вопроса «оплатят ли» это решающее.
5. НЕ правила: определения терминов, реквизиты, порядок расчёта премии, ПДн-разделы, тарифные
   таблицы (нетто/брутто-ставка, «средняя страховая сумма» ≠ лимит!), маркетинг.
6. Скидка на услугу = услуга НЕ покрыта → `excluded`, condition «только скидка N%».
7. `limit_amount` — только явный лимит («4 зуба», «10 сеансов», «30%», сумма в рублях).

## Промпт A — «ПРОГРАММА» (объём услуг + исключения программы)
*Примеры: СОГАЗ «Комплексное мед. обслуживание с франшизой», приложения-программы страховых.*
- Извлекать ПОЛНОСТЬЮ: (а) все стоматологические пункты поимённо; (б) амбулаторные по группам
  (приёмы, манипуляции, лаборатория, инструментальная диагностика, физио, документы);
  (в) ВСЕ исключения (раздел «Исключения из программы»): заболевания — группами по пунктам,
  услуги — поимённо; (г) ограничения объёма из таблиц («КТ 1 раз», «массаж 10 сеансов»);
  (д) порядок получения (§0 п. 4) и франшизу.
- Целевой объём: **25–100 правил**; целевое покрытие листовых пунктов **≥95%**.

## Промпт B — «ПРАВИЛА СК» (общие правила страхования)
*Примеры: Правила ДМС РЕСО (ред. 01.04.2023), Правила ДМС Ингосстрах/Альфа.*
- Извлекать: общие исключения покрытия (`Страховщик не оплачивает`, `не является страховым случаем`),
  общесистемные механики (согласование учреждения, расширение перечня допсоглашением, расходы после
  окончания договора, возмещение наличными по согласованию) + всё стоматологически-релевантное.
- **Отличать исключения КОНКРЕТНОЙ программы от общих исключений правил** (в РЕСО раздел «8.
  Исключения» относится к программе «Здоровье без границ», а общие — п. 5.2–5.6 и 11.6).
  Ошибка типа «взял чужие исключения как общие» — самая дорогая в этом типе.
- НЕ извлекать: заключение/расторжение, премии, ПДн, репатриационную переписку (кроме исключений).
- `program_name = NULL`, кроме приложений-программ внутри того же файла (у них — своё имя).
- Целевой объём: 10–40 правил.

## Промпт C — «ВЕБ-СНАПШОТ» (корп-страницы, FAQ, маркетинг)
*Примеры: ВШЭ-СОГАЗ, РЕСО корп-стоматология, РЕСО механика уровней.*
- Только конкретные обещания услуг и явные исключения/«за доплату»/«только скидка».
- `clause` = заголовок раздела страницы или фраза-якорь в «ёлочках».
- ОМС-ликбез (что покрывает ОМС) в правила ДМС НЕ извлекать.
- Целевой объём: 3–15 правил; мало — норма.

## Промпт D — «ПЕРЕЧЕНЬ КЛИНИК / СПИСОК»
Правил покрытия не содержит → **0 правил**, это норма (не считать провалом экстракции).

## Промпт E — «МУЛЬТИПРОГРАММНЫЙ СБОРНИК» (>150 КБ, десятки программ)
*Пример: Правила ДМС ФЛ Ингосстрах 2020 — 1.1 МБ, 35 программ, 18 блоков исключений.*
1. Сначала **карта документа**: список программ (`Программа добровольного медицинского страхования`
   + следующая строка) и блоков исключений.
2. Общие исключения повторяются у каждой программы с РАЗНОЙ нумерацией → извлекать ОДИН раз
   (`program_name = NULL`) по каноническому блоку; в `clause` отмечать расхождение:
   `п. 3.1.11 (в ряде программ — п. 3.1.12)`.
3. Полностью извлекать программы, релевантные клинике (все стоматологические + поликлинические
   со стоматологическим блоком). Остальные — по решению, с явной пометкой в плане, что не бралось.
4. Верификация — по **scope-файлу** (склейка ровно тех разделов, что извлекались), а не по всему тексту.

# ФОРМЫ ПОДАЧИ УСЛОВИЙ (вторая ось: КАК написано, а не только ЧТО за документ)

Тип документа (A–E) задаёт **что извлекать**, форма подачи — **как читать**. Одна страховая
любит сплошной текст, другая — таблицы; в одном документе встречаются обе формы. Всегда
определить форму каждого блока ДО извлечения.

## Ф1 — Сплошной текст с нумерованными пунктами
*«3.2.7. Хирургическая стоматология: удаление зубов (простое, сложное)…»*
Основная форма правил СК и программ. Пункт = clause, услуги внутри пункта дробятся (§0 п. 3).

## Ф2 — Маркированные списки «Предоставляется / Не оказывается»
*РЕСО 5.1: «Предоставляемые услуги: • консультации… Не оказываются: • имплантация зубов…»*
- Номеров у пунктов нет → clause = `Программа 5.1 «дословная фраза-якорь»`.
- **Обязательно извлекать ОБА списка**: «не оказываются» — источник самых ценных excluded-правил
  (именно там нашлось «удаление дистопированных, ретенированных зубов» у РЕСО).
- Порядок в списке значения не имеет; каждый буллет = отдельное правило.

## Ф3 — ТАБЛИЦЫ ограничений объёма
*СОГАЗ: колонка «Ограничения объёма услуг в течение страхового года»: «Компьютерная томография — 1 раз»,
«Классический лечебный массаж — не более 10 сеансов (не более 3 массажных единиц за сеанс)».*
- **Строка таблицы = одно правило** `conditional`; значение из колонки-ограничения → `limit_amount`,
  расшифровка → `condition_text`.
- Заголовок колонки задаёт ПЕРИОД действия лимита («в течение одного страхового года») — он
  обязан попасть в `condition_text`, иначе лимит читается как «навсегда».
- clause = номер пункта, к которому таблица относится (таблицы обычно идут сразу за пунктом).
- **Опасность pdftotext:** в извлечённом тексте колонки разъезжаются, числа оказываются
  отдельными строками ниже подписей. Перед извлечением сверить количество строк-подписей и
  количество чисел; при расхождении читать соответствующие страницы PDF глазами.

## Ф4 — Таблицы выплат (проценты страховой суммы)
*Альфа: «перелом постоянного зуба — 1, максимум при множественных — 10; потеря зуба — 2, максимум — 20».*
- Это НС-выплаты, а не оплата лечения: verdict `conditional`, в `limit_amount` — процент,
  в `condition_text` — «выплата по таблице, % страховой суммы».
- Число под подписью в отдельной строке — норма для pdftotext; сопоставлять по порядку строк.

## Ф5 — Сноски и примечания
*Ингосстрах, сноска 2: «Зубопротезные услуги оплачиваются только с применением металлических коронок…».*
- Сноски меняют смысл пункта и часто содержат ГЛАВНОЕ условие. Читать всегда; в clause указывать
  «п. X, сноска N «фраза»».
- Маркер сноски в тексте выглядит как прилипшая цифра («услуги2») — не путать с номером пункта.

## Ф6 — Прейскуранты и приложения клиники (Excel/Word)
*Ожидаются от владельца: «Томск_Максимум_3г», «Амб. взрослые; Стоматология в ЛПУ».*
- Лист = программа, строка = услуга, колонки = включено / лимит / доплата.
- «Включено: нет» → excluded; «доплата X%» → excluded + condition «только со скидкой/доплатой».
- Названия услуг из прейскуранта — лучший источник `service_pattern` (совпадают с речью врача).

## Ф7 — Скан без текстового слоя
`document_text` пуст или содержит мусор → правила НЕ извлекаются, документ помечается как
требующий OCR. Придумывать правила по названию файла запрещено.

## ВЕРИФИКАТОР (обязателен после каждого документа)
`python3 /opt/sib-intake/verify_rules.py <docId-префикс> [scope-файл]` — печатает:
1. **ЛИСТОВЫЕ ПУНКТЫ** — сколько листовых (не-контейнерных) пунктов документа покрыто правилами.
   Норма: ≥95%. Непокрытые — либо добрать, либо обосновать (оглавление, реквизиты, тарифы).
2. **ЯКОРЯ clause** — каждый номер/фраза находится в тексте (нормализация переносов PDF). Норма: 0.
3. **ЦЕЛОСТНОСТЬ** — нет правил без clause, нет `conditional` без `condition_text`, verdict из словаря.
4. **ЭТАЛОННЫЕ УСЛУГИ** — удален/имплант/протезир/ортодонт/кариес/пародонт/коронк: если в тексте
   упоминается, а правил 0 — предупреждение.
5. Спот-чек: 5 правил сверить с исходным текстом дословно (verdict не перепутан).
6. Коллизии паттернов (SQL): `select a.service_pattern, b.service_pattern from coverage_rule a join
   coverage_rule b on a.id<>b.id and a.document_id=b.document_id and coalesce(a.program_name,'')=
   coalesce(b.program_name,'') and b.service_pattern like '%'||a.service_pattern||'%'` → должно быть 0 строк.

**Провал любого пункта → чинить правила И промпт (если причина в промпте), прогонять заново.**

# ЧЕК-ЛИСТ: ДОБАВЛЕНИЕ НОВОГО ИСТОЧНИКА (проверять КАЖДЫЙ раз)

Требование владельца 2026-07-25: при добавлении файла проверять, что он проведён по всему
процессу, а не просто скачан. Автопроверка — `tools/audit-sources.py` (боевая копия
`/opt/sib-intake/audit_sources.py`), она печатает все нарушения этого чек-листа.

1. **Файл скачан локально** в `/opt/sib-storage/programs/` — внешняя ссылка может исчезнуть
   или подмениться другой редакцией.
2. **`source_url`** — страница, где страховая публикует документ (куда смотреть обновление).
3. **`file_url`** — прямая ссылка на файл. Без неё недельный поллер сверит только текст страницы.
4. **`sha256`** проставлен (`sha_fix.py`) — иначе первый прогон поллера сочтёт файл изменившимся
   и создаст ложную редакцию.
5. **Проверено юрлицо в тексте**: письма приходят от конкретной компании (было: загрузил правила
   ООО «ОСЖ РЕСО-Гарантия» вместо САО «РЕСО-Гарантия» — все правила пришлось удалить).
5a. **ПРОВЕРЕНА АКТУАЛЬНОСТЬ РЕДАКЦИИ — по реестру правил страховой, а не по первой ссылке из поиска.**
   Открыть раздел «Правила страхования» на сайте страховой, найти строку с ДАТОЙ НАЧАЛА ДЕЙСТВИЯ
   и брать файл оттуда. Затем сверить титул скачанного PDF: «Утверждены приказом № … от …» —
   дата в титуле должна соответствовать реестру. Было: у СОГАЗ загружена редакция 2015 года
   (в титуле ещё «Открытое акционерное общество»), тогда как действуют 003 от 31.01.2023 и
   143 от 01.02.2023; у Ингосстраха два документа названы выдуманными датами, а по титулу это
   приказы 2017 и 2019 годов. **Название документа в базе = фактический приказ из титула.**
5b. **Проверено, не подменился ли файл по постоянному адресу:** у РГС имя файла осталось
   `..._29.01.2021_.pdf`, хотя реестр показывает действие с 01.04.2023 — сверять содержимое (sha),
   а не имя файла.
6. **Документ относится к нашей клинике**, а не «пример» чужого договора (были удалены страница
   ВШЭ и программа СОГАЗ-«Северсталь»). Не подходит → не заводим вовсе.
7. **Текст извлечён** (`extract_doc_texts.py`), страниц > 0. Пусто → скан, нужен OCR (форма Ф7).
8. **Определён тип (A–E) и формы подачи (Ф1–Ф7)** — от них зависит, что и как извлекать.
9. **Экстракция проведена полностью**, а не заглушкой: ориентир — не меньше одного правила
   на 8 страниц текста; для правил СК со стоматологией — все пункты объёма и исключений.
10. **Верификатор пройден** (`verify_rules.py <pref> [scope]`): якоря найдены, целостность чистая,
    лимиты из таблиц не потеряны.
11. **Алиасы программ** заведены (`program_alias`), чтобы правила находились по строке из письма;
    если документа для программы нет — записать ПРИЧИНУ в `note` (она видна в сводке покрытия).
12. **Поллер отработал** по документу хотя бы раз — запись в `document_check`.
13. **Покрытие пересчитано**: `/coverage/sources` показывает новую долю пациентов.

## ПРОЦЕДУРА
1) Текст дока из `document_text` → локальный файл. 2) Тип документа → соответствующий промпт.
3) Экстракция → `.sql` (`delete from coverage_rule where document_id=…` + INSERT — идемпотентно).
