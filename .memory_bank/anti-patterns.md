# Anti-patterns — грабли sib

> Чеклист при ревью среза. Дополняй по мере находок (особенно от кодогена/LLM).

## 1. Доверять техническому отправителю пересланного письма
**Симптом:** в GuaranteeLetter попал email того, кто переслал, а не страховой.
**Convention:** извлекать **исходного** отправителя/дату/тему из блока пересылки (ADR D5).
**Детект:** From письма = разработчик/клиника, а не домен страховой.

## 2. Авто-удаление дублей
**Симптом:** код удаляет письмо/запись по совпадению.
**Convention:** дубли только **помечать**, показывать в админке (ADR D6). Не удалять.
**Детект:** `delete` по сигналам дубля.

## 3. Голый внешний вызов
**Симптом:** прямой `imap` / `fetch` / `openai(...)` в server action/компоненте без обёртки.
**Convention:** обёртка — типизированный результат + Inngest-ретрай + user-facing ошибка (конституция §5).
**Детект:** сетевой вызов вне `lib/`/Inngest-функции; `try/catch`, молча глотающий ошибку.

## 4. ПДн/секрет в логе
**Симптом:** ФИО/полис/диагноз/токен в `console.log`/трейсе.
**Convention:** маскирование PII; секреты не логируем (`.claude/rules/guardrails.md`).
**Детект:** лог объекта письма/пациента целиком.

## 5. Доверять форме LLM/внешних данных
**Симптом:** ответ OpenAI / тело письма используются без валидации схемой.
**Convention:** валидировать на границе (zod), фиксировать confidence, низкое → ручная очередь.
**Детект:** `JSON.parse(llm)` без схемы; прямое присвоение полей из распознавания.

## 6. Спека как аксиома
**Симптом:** поля/форматы из брифа захардкожены без проверки на реальных письмах.
**Convention:** гипотеза → проверка → ADR при расхождении (`source-of-truth.md`).


## Уроки парсинга, перенесённые из core/lessons.md (2026-07-25)

1. [2026-07-23] Писал регэксп-правила по красивому `pdftotext -layout` → на бою промахи: парсер
   извлекает БЕЗ `-layout` (поточный порядок другой) → правило: правила/отладку писать ТОЛЬКО на
   том тексте, который даёт боевой `pdf_text()`; валидировать на нём же.
2. [2026-07-23] Казалось «LLM-значения = эталон» → офлайн-сверка показала: LLM клала период ГП в
   coverageFrom/To (по схеме там период ПОЛИСА; срок ГП живёт в validUntil) → правило: «золотой
   корпус» сверяет ФОРМУ, семантику полей решает схема+ADR, mismatch ≠ автоматически ошибка правила.
3. [2026-07-23] Формы-бланки (СОГАЗ-направления): в поточном тексте ЗНАЧЕНИЯ идут НАД
   подписями-лейблами («22.01.2026 22.02.2026 \n Дата начала…»), и пара дат стоит перед парой
   лейблов → правило: для форм пробовать паттерн «значение(я) ПЕРЕД лейблом», не только после.
4. [2026-07-23] Файл-first «в лоб» (любое значение из файла бьёт тело) → Балта: слабый FIO2-фолбэк
   из PDF перебил сильную метку «на имя …» из тела → правило: приоритет источника НЕ выше приоритета
   СИЛЫ извлечения (метка > маска > позиционный фолбэк); сначала сила, потом источник.
5. [2026-07-23] Шапка табличного файла как ДАННЫЕ: повтор заголовка перед каждой секцией
   (Ингосстрах «Полис|Фамилия|…», Энергогарант «Полис ДМС») парсился как пациент/полис →
   правило: значения, равные именам колонок, режутся в источнике (FIO_BAD/явные гварды), а колонка
   «Дата открепления» В ШАПКЕ не делает документ откреплением — тип решает ИМЯ ФАЙЛА/титул.
