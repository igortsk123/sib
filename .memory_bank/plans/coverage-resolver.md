# План: резолвер покрытия (маппинг программ + приоритет правил)

> Основание — сверка 488 правил с реальными письмами (2026-07-25): правила именно той программы
> нашлись лишь у 2537 из 7764 записей (33%). Причина — правила собирались от найденных документов,
> а не от частотности программ в письмах. Этот план включает уже собранные правила в работу.

## Что вскрыла сверка
1. Поле `guarantee_letter.services` **смешанное**: у СОГАЗ/Ингосстраха/РЕСО/Альфы там **названия
   программ** («Амб. взрослые; Стоматология в ЛПУ», «"Специализированная стоматология"»,
   «Стоматологическая помощь (уровень стом. услуг 2)», «Томск_Максимум_3г»), у ВСК/Совкомбанка/
   Зетты/Энергогаранта/РГС — **реальные услуги** («удаление ретинированных и дистопированных зубов»,
   «первичный прием стоматолога», «ОАК»). Резолвер обязан различать оба типа.
2. Названия программ в письмах пишутся вариативно (кавычки, порядок, «+», регистр) → нужен
   нормализованный алиас, а не сравнение подстрок.
3. Правила уровня СК у Ингосстраха запрещают почти всю стоматологию «кроме случаев, прямо
   предусмотренных Программой» → без приоритета «программа > правила СК» ответ будет ложным НЕТ.
4. `effective_from` у документов в основном пустой → выбор редакции на дату полиса не работает.

## Срез (UI→БД)
**Миграция 0020:**
- `program_alias` — {insurance_company_id, alias_norm (уник. в рамках СК), program_name, kind:
  program|service, note}. Заполняется по фактическим строкам писем.
- `coverage_rule.scope_level` — `program` | `insurer` (вычисляется из program_name).
- `coverage_rule.overridable` — true у правил СК с условием «кроме случаев, предусмотренных Программой».
- `program_document.effective_from` — проставить по известным редакциям.

**Резолвер** `lib/server/coverage/resolve.ts`: (insurerId, строки services, дата, опц. запрос услуги)
→ нормализация → алиасы → программы → правила программы (приоритет) + правила СК (те, что не
переопределены программным правилом того же service_class) → упорядоченный список с источником.

**Карточка письма:** блок «Что покрывает программа» — выжимка правил (ДА/НЕТ/УСЛОВНО/СОГЛАСОВАНИЕ)
с пунктом-обоснованием, вместо голых ссылок на PDF.

**Тесты:** unit на нормализацию/приоритет/переопределение/дату; e2e на карточку.

## Критерии готовности
- Доля писем, для которых резолвер находит правила именно их программы, — с 33% до ≥80%
  (для СК, у которых документы есть).
- Ингосстрах: по программе «Специализированная стоматология» удаление зуба = ДА, несмотря на
  запрет в общих правилах (проверка приоритета).
- Гейт зелёный, `/memory-check` чисто.

## Не входит (следующие шаги)
Добор документов по частотности (РГС 660 писем, Энергогарант 400, уровни РЕСО, Ингосстрах
«Поликлиника+ПНТР»); файлы клиники (СОГАЗ «Амб. взрослые; Стоматология в ЛПУ» — 1760 писем,
Альфа «Томск_*») — ожидаются от владельца; прецеденты по услугам (возможны для ВСК/Совкомбанка/
Зетты/РГС — там в письмах реальные услуги).

## Пауза (2026-08-11) — статус `partial`
Резолвер `lib/server/coverage/resolve.ts` и приоритет «программа > правила СК» реализованы
(D23–D27), правила разнесены. **Не закрыт главный критерий приёмки:** доля писем, для которых
резолвер находит правила ИМЕННО их программы (цель ≥80%) — метрика не измерена после доразноса.
**Остаток:** замер доли + добор документов по частотности (РГС, Энергогарант, уровни РЕСО) и файлы
клиники от владельца (СОГАЗ «Амб. взрослые»/«Стоматология в ЛПУ», Альфа «Томск_*») — они же
блокируют последние ~8% покрытия. Движения с 25.07 нет.

## Метрика замерена (2026-08-11) — 53,1%
Ключевой критерий приёмки наконец посчитан на проде тем же запросом, что и страница
`/coverage/sources`: **пациентов с известной программой 7704, правила их программы найдены
у 4091 → 53,1%** при цели ≥80%.

Разрыв (топ по пациентам, программ без правил):
РГС «амбулаторно-поликлиническая помощь» 712 · РГС «стоматология» 396 · Ингосстрах «ДМС Оптима»
296 / «Комплексная со стоматологией» 277 / «ДМС Стандарт (поликлиника + стоматология)» ~250 ·
Альфа «Томск» 260 · Ренессанс «амб.-поликлиническое детей» 110 · РЕСО «амбулаторная помощь» 104.
Это ровно те документы, которых нет: РГС/Ингосстрах/Ренессанс/РЕСО — добор по частотности,
Альфа «Томск_*» и СОГАЗ — файлы от владельца.

**Починено попутно:** разделитель программ рвал название по «+» ВНУТРИ скобок — «ДМС Стандарт
(поликлиника + стоматология)» превращался в две несуществующие программы. Исправлено в
`splitPrograms()` и в SQL сводки (`sources.ts`), покрыто unit-тестами: 1226 обрывков названий →
613 целых. Долю покрытия это не двигает (у программы всё равно нет документа), но справочник
программ перестал двоиться.

**Новая находка (не чинилось):** в справочнике есть битые названия программ с повторами букв —
СОГАЗ «тит мееееееееарк ао (газпром - козлов неееееи…» на 497 пациентов и «неееееовиков марк
страхования: с 01.01.2026…» на 302. Похоже на дефект извлечения (mojibake/дублирование символов)
в конкретном источнике — разобрать отдельно, это ~800 пациентов знаменателя.
