## ОЧЕРЕДЬ (по ценности для врача/регистратуры)

### Ф-A. Ответ на вопрос «можно ли делать X пациенту за Y» — ЯДРО ЦЕННОСТИ
Поле вопроса в карточке пациента: детерминированные гейты (прикреплён? → программа покрывает
услугу? → есть действующее ГП на неё (тип+зуб)? → срок? лимит?) → только неясное в mini-LLM
с выжимкой правил → ДА / НЕТ / ПО СОГЛАСОВАНИЮ / НУЖЕН ЗАПРОС ГП, каждый ответ с пунктом.
Основа готова: resolve + service-match + computePatientState. **Вместе с Ф-A закрыть Д2/Д3
честными состояниями:** «срок ГП не распознан — проверьте оригинал», «объём ГП не распознан».

### Ф-B. e2e на критические потоки (Д7) — долг конституции
Playwright: вход тест-логином → реестр (поиск/фильтр/карточка) → пациенты (список/карточка) →
/coverage (поиск/фильтры) → вопрос-ответ Ф-A. Прогон в гейте деплоя.

### Ф-C. Дораспознавание ГП (Д3, Д10) — ✅ ВЫПОЛНЕНО 25.07 (ADR D28)
Mojibake-фикс `rtf_text` (сырая cp1251 РЕСО), правила `reso_gp`/`ingos_gp`, расширение `sovcom_gp`;
регресс golden-PDF 0 mismatch + RTF-РЕСО 100% по номерам/датам; backfill только-пустых +227 ГП
(Д3 245→19, Д2 53→33, valid_until 435/536); coverage-коррекция РЕСО ×127 (по доказательству);
annul-гейт по номеру письма (13 ГП исключены из действующих). Остаток Д3: 8 сканов Ингосстраха (OCR).

### Ф-D. Генератор запроса ГП — ✅ ВЫПОЛНЕНО 25.07 (ADR D29)
Черновик reply-in-thread (Re: + In-Reply-To на последнее письмо страховой по пациенту), кнопки
«скопировать»/«скачать .eml» (X-Unsent). Появляется под вердиктами «запросить ГП»/«согласование».
SMTP-отправки нет — вручную из ящика ДМС.
