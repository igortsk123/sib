## ОЧЕРЕДЬ (по ценности для врача/регистратуры)

### Ф-A. Ответ на вопрос «можно ли делать X пациенту за Y» — ЯДРО ЦЕННОСТИ
Поле вопроса в карточке пациента: детерминированные гейты (прикреплён? → программа покрывает
услугу? → есть действующее ГП на неё (тип+зуб)? → срок? лимит?) → только неясное в mini-LLM
с выжимкой правил → ДА / НЕТ / ПО СОГЛАСОВАНИЮ / НУЖЕН ЗАПРОС ГП, каждый ответ с пунктом.
Основа готова: resolve + service-match + computePatientState. **Вместе с Ф-A закрыть Д2/Д3
честными состояниями:** «срок ГП не распознан — проверьте оригинал», «объём ГП не распознан».

### Ф-B. e2e на критические потоки (Д7) — долг конституции
Playwright: вход тест-логином → реестр (поиск/фильтр/карточка) → пациенты (список/карточка) →
/coverage (поиск/фильтры) → вопрос-ответ Ф-A. Прогон в гейте деплоя.

### Ф-C. Дораспознавание ГП (Д3, Д10) — план llm-to-deterministic L2–L6
Детерм-парсеры ГП-PDF Росгосстрах/Совкомбанк/ВСК/СОГАЗ/Зетта (label→value формы): срок,
услуги, диагноз, №полиса. Это же поднимет качество гейтов Ф-A. Плюс хвосты Д10:
скан «01.01»-дат + backfill, правило серийных annul.

### Ф-D. Генератор запроса ГП
Когда Ф-A ответил «нужен запрос»: черновик письма в страховую reply-in-thread (шаблон из
2–3 реальных тел dms@ Sent), кнопка «скопировать/скачать .eml». Отправка — вручную
(SMTP-запрет владельца в силе).

### Ф-E. Мелочи данных (Д1, Д6) — 1 заход
Дозавести 4 алиаса Д1 (томские — с причиной «файл клиники»); связать письма Ренессанса и РГС
с их программами правил (проверить, что пишут их письма в services на реальных примерах).

### Ф-F. UI-правки владельца
/coverage: убрать колонку «Программа», «Условие/лимит» — раскрытием по клику на услугу.

### Ждём от владельца (блокирует последние ~8% покрытия)
Приложения к договорам клиники: СОГАЗ «Амб. взрослые»/«Стоматология в ЛПУ» (уточнят типовые
условия), Альфа «Томск_Максимум/Премиум/Оптимум» (сейчас идут по правилам №367 без программ).
Опционально: реестры правил РЕСО/Ингосстраха от владельца — сверка редакций уже сделана через
сайт/API, но перечень от СК надёжнее.

## Критерии готовности этапа
- Ф-A отвечает на типовой вопрос ≤2 сек, без LLM в ≥50% случаев, каждый ответ с пунктом;
- Д2/Д3 отражены в UI честными состояниями (0 «молчаливых» неопределённостей);
- e2e зелёные в гейте; покрытие ≥92% держится; аудиты (источники, правила) чистые.
