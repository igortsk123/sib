# Ложные открепления (FULLRISK) + комплексный аудит статусов прикрепления

## Симптом (нашёл владелец)
Запись `38c8e41b-…` (registry) показана «Открепление», хотя пациент прикреплён.

## Диагноз (2026-07-31)
- Источник записи — `ИГС_…_КЛИНИКА СИБИРСКАЯ_FULLRISK.XLS` («Список застрахованных **на дату** 06.02.2026,
  По факту») — это **полный реестр прикреплённых**, не открепление.
- В шапке файла есть колонка «**Дата открепления**» (плановое окончание прикрепления). Тема/тело письма пустые →
  `status_of(combined)` матчит `'открепл'` **раньше** `'прикрепл'`/`'список застрахован'` → est='detach' на весь файл.
- Имя файла FULLRISK не содержит прикреп/откреп → фикс D19 (имя файла приоритетнее blob-keywords) не срабатывает.
- Это ТРЕТИЙ случай класса «шапка травит статус всего файла» (ИГС_ПРИКР 896, оговорка Альфы/Лучей 94, теперь FULLRISK).

## Масштаб (прод, 2026-07-31)
- 988×2 записи СИБИРСКАЯ FULLRISK + 1948 СОЛНЕЧНАЯ FULLRISK — все detach (ложно).
- `ИГС_ИЗМЕН_*` (списки изменений данных) — тоже detach (подозрительно, проверить).
- **1864 пациента** сейчас «не прикреплён» только из-за этих реестров (rn=1 событие = detach из FULLRISK).
- Настоящие открепления (`ИГС_ОТКР_*`) — отдельные файлы, их не трогаем.

## План
1. Семантика файлов: СОЛНЕЧНАЯ (чья клиника? скоуп org), ИГС_ОТКР (валидны как detach), ИГС_ИЗМЕН (→ other?).
2. Фикс `.mail-intake/extract_dataset.py`:
   - детект «реестр прикреплённых»: шапка с колонками «дата прикрепления» И «дата открепления» (или
     «список застрахованных на дату») → est файла игнорируется, статус ПО СТРОКЕ:
     enroll если откреп-дата пуста или >= даты реестра, иначе detach;
   - имя файла: `измен` → change-list (`other`);
   - `status_of`: не решать detach по одной лишь колонке-шапке.
3. Реклассификация прод-записей: dry-run отчёт → UPDATE (doc_type/approval_status), без удаления; лог.
4. Комплексный аудит: все уникальные файлы-источники detach/enroll по всем СК — проверить основание
   классификации (имя файла / blob / canc-колонка); выборочная сверка файлов.
5. Проверка после: счётчики attached/detached до/после, исходная запись, e2e-поток пациентов.
6. Гейт + память (lessons: третий случай класса; ADR) + /memory-check.
