# .doc-экстрактор для Энергогаранта (худшая очередь «проверить»)

## Проблема (аудит шаблонов/парсеров 2026-07-31)
- ЭГ шлёт направления/ГП в **.doc (старый Word)** — 46 файлов + 60 png-сканов. Экстрактора .doc
  в раннере нет → тексты вложений пустые, LLM работает «по телу письма».
- Итог: `referral` ЭГ — **21 из 44 в needs_review (48%)** — худший показатель по всем СК;
  карта СК честно говорит «нужен .doc-экстрактор (в очереди)».

## План
1. Экстрактор: `antiword`/`catdoc` (apt, лёгкие) в контейнер/на сервер раннера; в `extract_dataset.py`
   ветка `.doc` → текст (фолбэк: LibreOffice headless, если antiword падает; docx уже покрыт).
2. Прогнать по золотому корпусу ЭГ (валидация D21) — у ЭГ уже есть enroll-парсер списков,
   правило ГП/направления добавить в `rules_gp.py` при чёткой структуре бланка (дерево D33 §A5).
3. Повторный прогон ЭГ-писем с .doc: дозаполнение только-пустых полей (паттерн D28 backfill),
   снятие needs_review, где ключевые поля закрылись.
4. png-сканы (60): проверить, что vision-путь получает картинку из .eml (паттерн урока 18 —
   не путать логотипы с контентом).
5. Обновить карту `rules.parsing` ЭГ («Вложения .doc → парсер/экстрактор», убрать «в очереди»)
   и `doc_template` ЭГ (образец + gold_json).

## Критерии готовности
- Доля needs_review по ЭГ referral < 10%; тексты .doc извлекаются в живом приёме.
- Гейт: валидация по золотому корпусу ЭГ, unit на экстрактор-обёртку, /memory-check.

## Summary (2026-07-31) — выполнено
Причина очереди была не в пустых полях, а в невозможности СВЕРКИ: olefile-выжимка .doc теряла
числовые ячейки (полис) — анти-паттерн №23. Сделано: `doc_text` → antiword -m UTF-8 (фолбэк
catdoc → olefile), правило `eg_referral` в rules_gp (полис/ФИО+ДР/услуга/дата выдачи/срок 30 дн);

1 полис исправлен по маске. Очередь ЭГ-направлений **21→1 (2%)**, критерий <10% выполнен.
Карта parsing ЭГ и шаблон referral обновлены. png-сканы — vision-путь, без изменений (урок 18 учтён).
