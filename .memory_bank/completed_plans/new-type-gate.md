# Гейт новых типов писем (правило владельца, 2026-08-01)

## Требование владельца
Любое новое письмо: **есть шаблон → идёт по шаблону**; **нет шаблона → в общий список не грузим**,
вместо строк — алерт «есть новые типы писем, для загрузки напишите в поддержку». Раз в день —
Telegram владельцу (служебный): «есть новые типы писем (N шт.), нужно писать парсер».

## Решение (ADR D48)
- «Есть шаблон» = `doc_template(insurer, doc_type)` со статусом ≠ `new`. Письмо без опознанной СК = нет шаблона.
- Записи нового типа **распознаются и сохраняются**, но с флагом `is_held=true` (в выборки реестра/
  экспорта/пациентов/покрытия не попадают). Так «дозагрузка» после написания парсера = снятие флага,
  без повторного парсинга. Self-healing создание шаблона (status `new`, образец письма) остаётся —
  это заготовка для поддержки; error_report остаётся.
- Активация: смена статуса шаблона из `new` (действие в UI шаблонов) → unhold записей пары.
- Баннер в реестре: N held-писем по организации + текст «напишите в поддержку».
- Дайджест: скрипт `npm run digest:newtypes` (sendMessage платформенным админам с telegramUserId,
  без ПДн: только СК/тип/кол-во), systemd-таймер на сервере раз в день.

## Шаги
1. Миграция: `guarantee_letter.is_held` (expand-only). 2. Гейт в `ingest.ts`. 3. Фильтры выборок.
4. Баннер. 5. Unhold в templates/actions. 6. Дайджест+таймер. 7. Тесты, гейт, деплой, e2e (сервер).
