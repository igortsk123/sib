# План: гарантийные письма → правила покрытия (со сроками, авто)

Запрос владельца 26.07: «ГП тоже в правила разносить — просто со сроком действия; накопившиеся
разнеси, будущее — автоматически при добавлениях».

## Дизайн (внимательно)

1. **Что это за правила.** ГП — индивидуальное согласование, НЕ оферта программы. Поэтому
   разносим как **прецеденты**: «страховая такое оплачивала по ГП» → verdict **needs_approval**
   («по согласованию»). Ответ регистратуре: «страховая оплачивала эту услугу по ГП (последний
   раз до <срок>), запросите гарантийное письмо». НЕ 'covered' — гарантий на будущее ГП не даёт;
   действующее ГП конкретного пациента и так даёт «ДА» гейтом-2 карточки.
2. **Сроки — ОБЯЗАТЕЛЬНО** (требование владельца): в каждом правиле-прецеденте фиксируются
   срок действия последнего ГП и его дата: `condition_text = «прецеденты: N гарантийных писем,
   последнее от <дата> со сроком до <valid_until>»`, `clause = «ГП №<номер последнего>»`.
   При новых ГП прогон обновляет срок/счётчик (идемпотентный delete+insert по документу).
3. **Куда.** Виртуальный документ на СК: `doc_kind='gp_practice'`,
   title «Практика гарантийных писем — <СК>», `source_url=internal://gp-practice/<ck>`,
   notes-пояснение. `scope_level='insurer'`, `overridable=true` → официальная программа ВСЕГДА
   сильнее прецедента; catch-all не задевается (needs_approval ≠ excluded).
4. **Скоуп СК.** Только страховые БЕЗ опубликованных правил (Д8: Совкомбанк, Лучи, ВСК,
   Балт Ассистанс…) — там ГП единственный источник фактики. СК с официальными правилами
   не замусориваем прецедентами (их ГП работают в карточке пациента напрямую).
5. **Нормализация услуг.** lower/трим/схлопнутые пробелы, 5–200 симв; ФИО-паттерны вырезаются
   (ПДн в правило не попадает); группировка одинаковых услуг: count писем, max(дата), max(срок);
   топ-200 услуг на СК (отсечка мусорного хвоста).
6. **Автоматика.** `gp_practice_rules.py` (SQL-only, идемпотентный) на сервере:
   ежедневный таймер `sib-gp-rules.timer` 05:10 (после ночного бэкапа и review-sweep) +
   в конец недельной цепочки `sib-programs.service`. Новые ГП попадают в правила ≤ суток.
7. **Гейт-ответ.** `rulesForService` находит прецедент по словам услуги → «НУЖНО СОГЛАСОВАНИЕ»
   с пунктом «ГП №…» и сроком; `/coverage` показывает прецеденты с документом «Практика ГП».

> **ИТОГ:** 227 прецедентов (Совкомбанк 86, ВСК 107, Лучи 32, Балт 2) со сроками; таймер 05:10 + недельная цепочка. Д8 закрыт. ADR D38.

## Шаги
1. ✅ План.
2. Скрипт → dry (счёт по СК) → apply.
3. Таймер + вставка в programs-цепочку.
4. Проверка: /coverage (правила видны), ответ по услуге из ГП Совкомбанка → «по согласованию» с №ГП и сроком.
5. Память (ADR), синк, коммит.
